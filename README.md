# 筆界ステーション（作業メモ）

## パソコンで見る方法

1. このフォルダでターミナル（文字でパソコンに命令する画面）を開きます。
2. 次のように入力して Enter を押します。

   ```
   npm run dev
   ```

3. ブラウザで http://localhost:4321 を開きます（自分のパソコンの中だけで見られるアドレスです）。
4. 終わるときは、ターミナルで `Ctrl + C` を押します。

## 記事を増やす方法

1. `src/content/articles/` に、半角英数字のファイル名で `.md` ファイルを作ります（例：`2026-11-hoge.md`）。
   ファイル名がそのまま記事のアドレスになります。
2. いちばん上に、次の項目を書きます（`---` で囲みます）。

   ```
   ---
   title: 記事のタイトル
   pubDate: 2026-11-04
   category: souzoku        # seido / kyokai / sokuryo / kiki / toki / shiken / kiso のどれか
   level: easy              # easy（やさしい）/ normal（ふつう）/ expert（専門）
   sourceName: 出典の名前
   sourceUrl: https://...
   summary: 要約（自分の言葉で。1〜2文・100字くらい。民間の記事は細かい数字や要点まで書かない）
   comment: ひとことコメント
   tags:
     - タグ1
   ---
   ```

3. その下に、本文を書きたければ書きます（なくてもOK）。
4. 下書きの間は `draft: true` を足すと、サイトに出ません。
5. 記事には、図解を少なくとも1枚つけます（流れ・年表・比べる図など。本文にあることだけを図にします）。図は `public/images/kiso/` に SVG で置き、ほかの記事の `<figure class="figure">` と同じ形で入れます。

## 発車標（ニュース）に出す方法

Googleアラートの下書き（`src/content/articles/inbox/`）のうち、記事にするほどではないけれど紹介したいニュースは、見出しとリンクだけを「発車標」に出せます。

1. 下書きの `category`（路線の色の印になります）と `level` を合わせます。
2. `feed: false` を `feed: true` に変えます（`draft: true` のままでOK。要約やひとことは出ません）。
3. トップページ・各のりばの発車標には新しい順に数件だけ、`/news/` には月ごとにすべて並びます（古いものも消えません）。
4. 元の記事が消えてリンクが切れたものは、ファイルを削除するか `feed: false` にもどします。
   リンク切れは `npm run news-check` で調べられます（見られなくなったものを一覧にします。ファイルは書きかえません）。

- 見出しの最後の「 - PR TIMES」のような媒体名は、自動で出典のほうに分けます。
- 出典の名前を変えたいときは `sourceName` を書きかえます（アドレスのままなら自動で決めます。表示名の一覧は `src/data/news.ts`）。
- きちんとした記事にした（`draft: false`）ものにも `feed: true` を書けば、発車標に出せます。

## カテゴリ（路線）を増やす方法

`src/data/lines.ts` の一覧に1行足します。

## 気をつけること

- 運営者の本名・事務所名・住所・職業など、個人が特定される情報は書かない。
- 依頼者や現場が特定される情報は書かない。
- 他サイトの文章や画像を転載しない。要約には必ず出典リンクを付ける。
- サンプル記事（`sample: true`）は、公開前に内容を確認して `sample: true` の行を消すか、記事ごと削除する。

## Googleアラートから下書きを作る仕組み

- 毎朝7時（日本時間）に、GitHubが Googleアラートを読み込みます。
- 新しい話題ごとに、`src/content/articles/inbox/` に下書き（`draft: true`）ができます。サイトには出ません。
- 使う話題は、元記事を確認して要約・ひとこと・カテゴリ・対象を書き、`draft: false` にして公開します。
- 使わない話題は、ファイルを削除します（同じリンクは二度と下書きになりません）。
- フィードのアドレスは、GitHubの Settings → Secrets and variables → Actions に `ALERT_FEEDS` という名前で入れます（1行に1つ）。公開されるファイルには書かないでください。
- GitHubで作られた下書きを手元に持ってくるときは `git pull` をします。

## 支線（シリーズ記事）の作り方

ある記事から枝分かれさせたい記事に、次の項目を足します。

```
branchFrom: hikkai-tokutei-seido   # 分かれ元の記事のファイル名（.md を除く）
branchOrder: 1                     # 支線の中での順番（1, 2, 3…）
station: 申請の流れ                 # 路線図に出す短い駅名（任意）
```

- 分かれ元の記事の駅名標に「支線 ↘」の案内が出ます。
- 支線の記事の駅名標は、左が1つ前（最初の記事なら分かれ元）、右が次の記事になります。
- 路線図（/rosenzu/）にも、枝分かれした線として表示されます。

## タグの付け方

- 記事の `tags:` には、`src/data/tags.ts`（タグ辞書）にある言葉だけを書けます。ほかの言葉を書くと、作り直すときにエラーで知らせます。
- 新しいタグが必要になったら、`src/data/tags.ts` の合うテーマに1行足します（`id` は半角英数字）。用語さくいんに同じ言葉があれば `glossary:` に用語の id を書くと、タグのページに説明が出ます。
- タグのページは `/tags/タグのid/`、テーマ一覧は `/tags/` です。
- 記事の最後の「関連する記事」は、同じタグが多い記事が自動で選ばれます。タグをきちんと付けるほど、つながりがよくなります。

## 車内の読み物（小説）の書き方

- 話は `src/content/stories/<列車>/<番号>.md` に書きます（例：`kakueki/11.md`）。アドレスは `/yomimono/kakueki/11/` になります。
- 列車の名前・色・登場人物・「これから停まる駅（予定）」は `src/data/trains.ts` にあります。
- いちばん上に書く項目：

  ```
  ---
  title: 話のタイトル
  train: kakueki          # kakueki（各駅停車）/ tokkyu（特急）
  no: 11                  # 第何話か
  pubDate: 2026-11-15     # 公開日。この日の0時すぎの自動公開から出ます
  summary: ひとことあらすじ
  point: 今日のひとこと（この話で学べること）
  learn:                  # もっと知りたい方へ（記事のファイル名。.md を除く）
    - hikkai-to-shoyukenkai
  ---
  ```

- 公開日が先の話は、その日の朝まで出ません（手元の確認用サーバーでは、先の話も「公開予定」として見えます）。
- 特急の話を書いたら、`trains.ts` の `stops` から、その駅名を消してください。
- 物語はフィクションです。実在の人物・地名・事務所や、依頼の内容がわかることは書かないでください。

## 筆界ステーションチェック（記事と図解をまとめて確認する）

手元の確認用画面だけにあるページです（本物のサイトには出ません）。

1. `npm run dev` で確認用画面を起動し、ブラウザで http://localhost:4321/station-check/ を開きます。
2. 記事が全部（公開中・下書き・発車標だけのもの）並びます。図解はその場で見られ、「本文を読む」で記事の中身も読めます。上の「下書き」「公開中」「図なし」などで、しぼりこめます。
3. 記事ごとに「OK」か「直してほしい」を選び、直してほしいところをメモに書きます。結果は `review/station-check.json` に自動で保存されます。
4. 終わったら「保存して Claude に渡す」を押します。Claude が待機していないときは、チャットで「ステーションチェックしたよ」と送ります。
